# 記録カードと記事のデータモデル

## 記録カード

一つのカードは、元記録から切り出した一つの出来事・判断・知見を表す。

| 項目 | 内容 |
|---|---|
| ID | 一意なカードID |
| 種別 | 開発ログ／ナレッジ／日報／週報 |
| 日付 | 元記録の日付。分からなければ未記録 |
| 見出し・本文 | 一つの話題を簡潔に表す |
| テーマ | 例：接続障害、レビュー、学習、品質改善 |
| 根拠状態 | 報告／確認済み／推定／未確認 |
| 出典 | 元文書、行、URL、成果物などへの参照 |
| 関連記録 | 要約元、関連Issue、親タスクなど |
| 影響・対応 | 必要な場合に、影響と対応、確認結果を記録 |

## 記事

記事は一つのテーマと読者を定め、複数のカードを起承転結へ配置する。

- 起承転結の各節はカードIDを参照する。
- 編集文をカードの根拠と結び付け、出典のない主張を検出できるようにする。
- 同じ出来事のログ・日報・週報が複数ある場合、出典関係を保持し、独立した複数事例として数えない。
- 事実、利用者の評価、編集上の解釈は区別する。
- 元カードが未確認または推定なら、記事側でも状態を維持する。

## 例

「接続障害の原因はAP切替だった」は、ログがAP切替の存在だけを示し原因を確定していない場合、記事の事実としては使わない。「AP切替は記録されていたが、障害原因との関係は未確認」と書き、根拠カードを付ける。
